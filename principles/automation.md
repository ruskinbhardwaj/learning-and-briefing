# Automation

Articles are generated by Claude following these principles. Generation runs on a schedule for morning briefings and on request for everything else.

## Morning briefing (scheduled)

Runs every weekday morning. Each run:

1. Reads `principles/` and the last five morning briefings, so it doesn't repeat items.
2. Searches for developments since the previous morning briefing (Monday covers the weekend) across all six topics in [topics.md](topics.md), using primary sources where possible.
3. Picks three to seven items that pass the editorial bar, most important first. A quiet day gets a short briefing; it never pads.
4. Writes `_posts/YYYY-MM-DD-morning-briefing.md` from [templates/morning.md](templates/morning.md).
5. Runs the pre-publish checklist in [editorial.md](editorial.md) and builds the site.
6. Opens a pull request titled "Morning briefing: D Month YYYY" and requests Addy's review. It is never merged automatically: Addy reviews and merges it.
7. Notes any item that deserves its own Briefing as an `article-request` issue.

## Other runs

- **On request.** Learning articles and Briefings are written when asked in the project or via an `article-request` issue.
- **Feedback sweep.** Open `edit-request` and `faq` issues are handled per [feedback.md](feedback.md).
- **Staleness sweep.** Articles past their review date are refreshed or superseded per [editorial.md](editorial.md).

Schedules and their prompts are kept in the project as routines; if one changes, update this file in the same change.
